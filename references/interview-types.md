# 面试类型指南

按面试侧重将评估维度与流程差异化。用户未指定时，从 JD 推断；用户指定时以用户为准。

## 岗位族选择规则

1. 从 JD 选择一个主要岗位族，作为 60%-80% 的评估权重。
2. 可叠加一至两个次要岗位族。例如“算法产品经理”可设产品 50%、数据/算法 30%、商务 20%。
3. 不按职位名称机械分类，要按入职后最重要的工作产出分类。
4. 每个岗位族至少设置一个工作样本（work sample），避免只靠问答判断。

## 核心面试类型

### 商务 / Business

**适用岗位**：BD、销售、市场、客户成功、商务拓展、投资关系。

**核心考察维度**：
- 商业敏锐度：市场判断、客户需求洞察、竞品认知
- 谈判与成交：客户关系、谈判策略、成交案例
- 结果量化：签单金额、客户数量、转化率、回款
- 沟通表达：向客户 / 高管呈现价值的能力

**典型提问方向**：
- 描述一次从 0 到 1 拿下关键客户的经历（STAR）
- 你如何判断一个客户是否值得投入？
- 遇到价格谈判僵局，你如何破局？
- 你个人的业绩 vs 团队 / 平台带来的业绩如何区分？

**典型流程**：简历筛选 → 案例分析 / 模拟谈判轮 → 行为 / 文化轮 → 高管终面。

### 业务 / Operations

**适用岗位**：运营、项目管理、交付、供应链、生产、流程优化。

**核心考察维度**：
- 执行与交付：项目按时按质交付能力、流程管理
- 跨部门协作：协调资源、推动多方落地
- 问题解决：突发问题、瓶颈、风险的处理
- 数据驱动：用数据衡量与改进业务

**典型提问方向**：
- 描述一个你推动跨部门落地的复杂项目（STAR）
- 项目延期 / 出问题时，你如何定位并止损？
- 你如何设定并追踪业务指标？
- 描述一次你优化流程、显著提效的经历。

**典型流程**：简历筛选 → 业务案例分析轮 → 行为 / 文化轮 → 用人经理终面。

### 研究 / Research

**适用岗位**：科学家、研究员、算法研究员、技术专家、研发负责人。

**核心考察维度**：
- 方法论与深度：技术判断、实验设计、理论功底
- 创新与原创性：论文、专利、技术突破
- 技术判断力：区分证据强弱、识别可行路径
- 落地能力：研究如何转化为真实决策 / 产品

**典型提问方向**：
- 深挖代表作：为什么选这个方法？失败过哪些路径？如何验证结论？
- 如何判断一个模型 / 实验结果的证据强弱？
- 你的研究如何影响真实决策（而非只发论文）？
- 面对一个开放问题，你如何拆解并设计验证方案？

**典型流程**：简历筛选 → 技术深度轮（论文 / 项目深挖）→ 研究案例轮 → 行为 / 文化轮 → 终面。

### 开发 / Development

**适用岗位**：软件工程师、算法工程师、平台工程师、架构师、技术负责人。

**核心考察维度**：
- 编码能力：算法、数据结构、代码质量
- 系统设计：架构、扩展性、权衡取舍
- 工程实践：测试、CI/CD、代码审查、可维护性
- 协作与交付：与产品 / 设计 / 业务协作

**典型提问方向**：
- coding 轮：见 `coding-interview.md`
- 系统设计：设计一个贴合业务场景的系统，讨论扩展性与权衡
- 工程实践：如何保证代码质量？如何处理技术债？
- 项目深挖：最有挑战的项目，技术难点与决策

**典型流程**：简历筛选 → coding 轮 → 系统设计轮 → 项目深挖 / 行为轮 → 终面。

### 产品 / Product

**适用岗位**：产品经理、平台产品、AI 产品、增长产品、产品负责人。

**核心考察维度**：问题定义、用户洞察、优先级、指标意识、技术协作、从 0 到 1 与迭代能力。

**工作样本**：给定一个模糊用户问题，要求产出问题定义、目标用户、成功指标、MVP 与取舍。

**验证问题**：
- 描述一次你主动否决高层需求的经历。你用了什么证据？
- 你负责的核心指标是什么？指标变化中有多少可归因于你的决策？
- 产品上线后结果不及预期时，你如何定位问题并决定继续、调整或停止？

**典型流程**：产品案例 → 项目深挖 → 技术/设计协作 → 行为与影响力 → 终面。

### 数据与分析 / Data & Analytics

**适用岗位**：数据分析师、数据科学家、BI、量化分析、增长分析。

**核心考察维度**：问题转译、SQL/Python、统计推断、实验设计、指标口径、洞察沟通。

**工作样本**：给出不完整数据与业务问题，要求定义指标、检查数据质量、提出分析路径并解释局限。

**验证问题**：
- 描述一次你的分析结论被业务挑战或推翻的经历。
- 如何识别相关性、因果性与选择偏差？
- 同一指标在两个看板不一致，你如何定位口径与数据链路？

**典型流程**：数据案例/SQL → 统计与实验设计 → 项目深挖 → 业务沟通 → 终面。

### 设计 / Design

**适用岗位**：产品设计、UX/UI、用户研究、服务设计、品牌设计。

**核心考察维度**：问题发现、用户研究、信息架构、交互推理、视觉执行、反馈迭代。

**工作样本**：作品集深挖或现场 critique，重点观察决策依据而非成品美观度。

**验证问题**：
- 作品中哪个关键决策由你作出？有哪些方案被放弃？
- 当研究结论与业务目标冲突时，你如何处理？
- 描述一次设计上线后被数据或用户反馈证伪的经历。

**典型流程**：作品集审查 → 设计挑战/critique → 跨职能协作 → 行为与文化 → 终面。

### 人员管理 / People Management

**适用岗位**：团队负责人、部门经理、总监、VP、技术管理者。

**核心考察维度**：招聘与组队、目标分解、绩效反馈、人才培养、冲突处理、组织设计。

**工作样本**：给定团队绩效与人员情境，要求制定 30/60/90 天行动方案。

**验证问题**：
- 描述一个你长期辅导但最终仍未达标的下属案例。你做了什么？
- 最近一年你团队中最优秀和最困难的人分别是谁？你如何管理？
- 你做过什么组织机制改变？哪些结果能证明改变有效？

**典型流程**：管理案例 → 团队与绩效深挖 → 跨部门影响力 → 价值观与高管终面。

### 质量、法规与合规 / Quality, Regulatory & Compliance

**适用岗位**：QA、QC、RA、GxP、CSV、法务合规、隐私与安全治理。

**核心考察维度**：法规理解、风险分级、证据与记录、偏差/CAPA、审计应对、业务平衡。

**工作样本**：给定偏差、审计发现或变更控制情境，要求完成风险判断与处置路径。

**验证问题**：
- 描述一次你坚持合规要求并与业务发生冲突的经历。
- 如何区分根因、直接原因与系统性原因？
- 举例说明一次 CAPA 没有效果，你如何发现并纠正？

**典型流程**：法规/质量基础 → 情境案例 → 审计/偏差深挖 → 行为与独立性 → 终面。

### 制造、实验与工程现场 / Manufacturing, Lab & Field Engineering

**适用岗位**：生产、工艺开发、实验科学家、自动化工程师、设备与现场工程师。

**核心考察维度**：实验/工艺设计、故障排查、数据完整性、安全、放大与转移、现场执行。

**工作样本**：给出产率下降、设备漂移、实验失败或工艺偏差，要求构建排查树与验证计划。

**验证问题**：
- 描述一次重复实验无法复现时的排查顺序。
- 你如何判断问题来自样品、方法、设备、操作还是环境？
- 从小试到中试/生产放大时，你如何识别关键参数与失败模式？

**典型流程**：技术基础 → 故障排查案例 → 现场/实验工作样本 → 安全质量行为 → 终面。

### 客户成功与解决方案 / Customer Success & Solutions

**适用岗位**：客户成功、解决方案工程师、售前、实施顾问、Forward Deployed Engineer。

**核心考察维度**：需求澄清、技术转译、实施交付、客户关系、采用率与续约、升级管理。

**工作样本**：模拟客户发现会议或对一个失败上线项目制定恢复计划。

**验证问题**：
- 客户提出错误解决方案时，你如何纠正而不破坏关系？
- 描述一次客户即将流失，你如何识别、干预并衡量结果？
- 当销售承诺超过产品能力时，你如何处理？

**典型流程**：客户情境模拟 → 技术/产品理解 → 项目复盘 → 沟通与行为 → 终面。

### 职能支持 / Corporate Functions

**适用岗位**：财务、采购、人力资源、行政、法务、战略与企业发展。

**核心考察维度**：专业判断、内部客户管理、风险控制、数据准确性、流程效率、保密与诚信。

**工作样本**：使用脱敏材料完成专业判断，例如预算偏差分析、供应商评估或人员方案。

**验证问题**：
- 描述一次你发现业务数据或流程存在重大问题的经历。
- 当内部客户要求绕过流程时，你如何处理？
- 你如何衡量职能工作的业务价值，而不是只衡量完成量？

**典型流程**：专业能力 → 业务情境 → 利益相关方协作 → 诚信与判断 → 终面。

## 混合与定制

- 岗位常为混合型（如「研究 + 开发」），按 JD 权重组合维度与轮次。
- 用户可指定额外侧重（如「侧重管理」「侧重英语」），在对应维度加重提问与流程环节。
- 所有类型都保留行为 / 文化轮，用于验证行为特征与价值观。
- 对敏感岗位（财务、合规、医疗、人员决策）增加独立判断与伦理情境，但不得基于受保护特征进行评价。
