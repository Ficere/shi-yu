# 简历四维拆解框架

将候选人信息拆解为四个维度，分别列出并排序。核心原则：**只陈述能从材料中确认的内容，推断内容明确标注，绝不把推断当事实。**

## 四个维度

### 1. 技能 Skills

覆盖候选人的可迁移能力与知识储备：

- **硬技能**：技术栈、工具、方法论（如 Python、AlphaFold、分子动力学、SQL、谈判、财务建模）
- **软技能**：沟通、领导、协作、抗压、跨部门协调
- **领域知识**：行业认知、法规、市场理解
- **语言**：中英文等语言能力

排序键：与 JD 相关性（第一）→ 熟练度证据强度（第二，是否有项目 / 成果佐证）。

### 2. 经验 Experience

覆盖候选人的履历轨迹：

- 项目 / 岗位经历、年限、行业、公司规模与阶段
- 项目复杂度（技术难度、协作规模、预算、周期）
- 角色与责任（执行者 / 负责人 / 决策者）
- 行业与岗位的连续性

排序键：与 JD 相关度（第一）→ 深度与复杂度（第二）→ 时间远近（第三，越近权重越高）。

### 3. 行为特征 Behavioral traits

从经历与表述中推断的工作风格与价值观：

- 工作风格：结果导向 / 过程导向、主动 / 被动、独立 / 协作
- 价值观：对质量、速度、风险、创新的态度
- 协作模式：跨部门、上下级、客户关系处理方式
- 动机：跳槽原因、职业诉求、稳定性信号

排序键：证据强度（是否有具体事例支撑，第一）→ 与岗位文化匹配度（第二）。

**注意**：行为特征几乎都是推断，务必标注「推断 / 待验证」，并在面试提问中作为验证点。

### 4. 业务影响 Business impact

覆盖候选人创造的可衡量价值：

- 量化成果：收入、成本、效率、成功率、规模、周期缩短
- 可衡量贡献：项目落地、产品上线、专利、论文、获奖
- ROI 与杠杆：投入产出比、影响范围

排序键：量化程度（第一，有数字 > 有定性描述 > 无描述）→ 与岗位目标的相关性（第二）。

## 拆解操作要点

1. **逐条提取**：先按时间线通读，再按四维归类，避免遗漏。
2. **标注证据等级**：
   - `[陈述]`：简历明确写出
   - `[推断]`：从上下文合理推断
   - `[缺失]`：材料中完全没有，需在面试确认
3. **量化缺失即风险**：业务影响若只有定性描述（「显著提升」「大幅优化」），标记为「量化待验证」。
4. **识别红旗**：跳槽频繁、空窗期、职级倒退、职责范围异常缩小、表述含糊（「参与」「协助」高频出现）、成果无法归因到个人。
5. **区分个人 vs 团队**：对「主导」「负责」等词保持警惕，追问个人实际贡献。

## 排序输出格式

每个维度输出为有序列表，每项包含：

```
[排序名次] 条目内容 —— [证据等级] [与 JD 关系说明]
```

示例：

```
技能维度：
1. 抗体可开发性预测（AlphaFold + MD）—— [陈述] 直接命中 JD 核心要求
2. Python 工程化能力 —— [推断] 支撑岗位的算法落地要求
3. 团队管理 —— [推断] JD 要求带团队，简历仅「主导」一词，待验证
```
