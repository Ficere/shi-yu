# JD 逐条对照框架

简历分析以 JD 为主线，不再把技能、经验、行为特征和业务影响重复归类成四套长清单。核心原则：**只展示影响岗位判断的信息，材料没有写明时标记为待确认，不把推断当事实。**

## 操作顺序

1. 从 JD 提取 5-8 条关键要求，must-have 优先。
2. 为每条要求查找简历中的直接证据，只保留最相关的 1-2 条。
3. 给出匹配判断：匹配 / 部分匹配 / 证据不足 / 不匹配。
4. 每行只写一个待确认点；没有必要确认时写“无需重点追问”。
5. 只在 JD 未覆盖但会显著影响录用判断时增加“补充观察”，最多 3 条。

## 默认输出

| JD 关键要求 | 简历证据 | 判断 | 待确认点 |
|-------------|----------|------|----------|
| 熟悉 AlphaFold / MD | 5 年计算科学经验，3 个抗体项目 | 匹配 | 在项目中承担的具体决策 |
| 带领团队 | 简历使用“主导”，未写汇报人数 | 证据不足 | 管理范围与实际职责 |
| 推动项目落地 | 写明进入项目决策，未说明结果 | 部分匹配 | 如何影响实验或业务决策 |

## 内部检查视角

技能、经验、行为和业务影响仍可作为面试官内部检查视角，但不默认单独输出：

- **技能**：是否有项目或成果支撑，而非只出现关键词。
- **经验**：规模、复杂度、角色和时间远近是否匹配。
- **行为**：只能形成待验证的工作行为假设，不能贴人格标签。
- **业务影响**：结果口径、个人贡献和影响范围是否清楚。

## 用词规则

- 用“证据不足 / 待确认”替代“缺失 / 存疑 / 夸大 / 红旗”。
- “主导”“负责”等词只表示需要澄清职责，不暗示候选人不诚实。
- 空窗、跳槽、转行只询问事实背景和职业选择，不推断稳定性或忠诚度。
- 不把年龄、性别、婚育、民族、宗教、残障、健康等受保护特征用于匹配判断。
- 不重复抄写 JD 和简历；每格尽量一行，整体应能快速扫描。
