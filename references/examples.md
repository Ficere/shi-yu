# 场景示例

以下示例展示不同面试类型下的完整输出结构。示例为演示格式，实际执行时需基于真实 JD 与候选人信息填充。

## 示例一：开发岗（含 coding 要求）

**输入**：
```
JD：后端工程师，Python / Go，负责高并发推荐系统，要求扎实算法与系统设计。
候选人：3 年 Python 后端，做过推荐服务，熟悉 Redis / Kafka，简历有量化指标。
要求：考察 coding 能力。
```

**四维拆解（节选）**：
- 技能：Python（[陈述]）、Redis / Kafka（[陈述]）、系统设计（[推断]，简历未体现规模）
- 经验：3 年后端、推荐服务（[陈述]），高并发规模（[缺失]）
- 行为特征：结果导向（[推断]，有量化指标）
- 业务影响：接口延迟降低 40%（[陈述]，量化待验证口径）

**匹配评估**：整体 78/100。优势是推荐系统经验对口；缺口是高并发 / 大规模系统经验证据不足；风险是「降低 40%」口径未说明。

**关键提问（节选）**：
- 推荐服务 QPS 峰值多少？瓶颈在哪？如何优化？（验证高并发经验）
- 「延迟降低 40%」的测量口径与对比基准是什么？（量化追问）
- 系统设计：设计一个支持千万 DAU 的推荐 feed，讨论缓存、消息队列、一致性。

**面试流程**：coding 轮 → 系统设计轮 → 项目深挖 / 行为轮 → 终面。

**coding 题（示例）**：
- LeetCode 146 LRU 缓存（Medium）：考察哈希 + 双向链表，贴合缓存 / Redis 场景。
- LeetCode 3 无重复字符的最长子串（Medium）：滑动窗口，考察字符串处理。
- 追问：LRU 如何用 Redis 近似实现？数据流场景如何扩展？

## 示例二：研究岗

**输入**：
```
JD：蛋白质设计算法负责人，要求 AlphaFold / MD，带团队落地抗体优化。
候选人：AI 制药公司计算科学家，5 年，主导 3 个抗体可开发性项目。
要求：侧重研究。
```

**四维拆解（节选）**：
- 技能：结构预测、MD、抗体可开发性（[陈述]）、团队管理（[推断]）
- 经验：5 年、3 个抗体项目、技术负责人（[陈述]）
- 行为特征：有带人经验（[推断]，「主导」待验证）
- 业务影响：项目进入真实决策（[陈述]，量化程度待验证）

**匹配评估**：整体 82/100。优势是抗体计算经验直接对口；缺口是管理规模证据不足；风险是「主导」可能夸大个人贡献。

**关键提问（节选）**：
- 深挖代表作：为什么选这个方法？失败过哪些路径？如何验证结论？
- 如何判断结构模型 / MD 结果与实验数据的证据强弱？
- 你的研究如何影响真实项目决策（而非只发论文）？
- 你直接管理过几人？如何分配任务与培养下属？

**面试流程**：技术深度轮 → 研究案例轮 → 管理 / 行为轮 → 终面。

## 示例三：商务岗

**输入**：
```
JD：BD 总监，负责生物制药 CDMO 客户拓展，要求大客户谈判与业绩。
候选人：8 年 BD，服务过多家药企，有签单记录。
要求：侧重商务。
```

**四维拆解（节选）**：
- 技能：大客户谈判、客户关系（[陈述]）
- 经验：8 年 BD、药企客户（[陈述]）
- 行为特征：结果导向（[推断]）
- 业务影响：累计签单金额（[陈述]，需追问个人 vs 平台贡献）

**关键提问（节选）**：
- 描述一次从 0 到 1 拿下关键客户的经历（STAR）。
- 你个人的业绩 vs 公司平台带来的业绩如何区分？
- 遇到价格谈判僵局，你如何破局？

**面试流程**：案例分析 / 模拟谈判轮 → 行为 / 文化轮 → 高管终面。

## 示例四：业务 / 运营岗

**输入**：
```
JD：项目交付经理，负责跨部门协调，推动研发项目按期交付。
候选人：6 年 PM，做过多个跨部门项目，有流程优化案例。
要求：侧重业务。
```

**关键提问（节选）**：
- 描述一个你推动跨部门落地的复杂项目（STAR）。
- 项目延期 / 出问题时，你如何定位并止损？
- 描述一次你优化流程、显著提效的经历，具体数字？

**面试流程**：业务案例分析轮 → 行为 / 文化轮 → 用人经理终面。

## 示例五：AI 产品经理

**输入**：JD 要求把基础模型能力落地为企业产品；候选人有 4 年 SaaS 产品经验和一个 RAG 项目。

**评估重点**：问题定义、模型能力边界、评测指标、技术协作、客户发现。行为假设“能在不确定性下推进”需要用失败迭代案例验证。

**工作样本**：为企业知识助手定义用户、MVP、离线/在线指标、幻觉治理与三个月路线图。

## 示例六：数据科学家

**输入**：JD 要求实验设计与增长建模；候选人熟悉 Python/SQL，简历写“提升转化率 12%”。

**验证重点**：指标口径、实验随机化、样本量、污染、归因与个人贡献。

**coding 形式**：60 分钟 Notebook 工作样本，完成数据检查、基础分析和结果解释；算法题只作为次要证据。

## 示例七：数据工程师

**输入**：JD 要求实时数据管道与质量治理；候选人有 Spark/Kafka 经验。

**coding 形式**：SQL 去重与窗口题 + 流式事件乱序/重复处理设计。评分重点是数据正确性、幂等、监控与回溯方案。

## 示例八：产品设计师

**输入**：JD 要求复杂 B2B 工作台设计；候选人作品集以消费端 App 为主。

**验证重点**：信息密度、复杂流程、研究证据、设计系统与跨职能协作。通过作品集深挖和现场 critique 判断可迁移性。

## 示例九：工程经理

**输入**：JD 要求管理 10 人平台团队；候选人简历写“带领团队交付多个项目”。

**行为验证**：团队人数、直接汇报关系、绩效管理、招聘、低绩效处理、人员流失与组织机制。不能仅凭“带领”认定管理经验。

**工作样本**：根据一个交付不稳定、士气下降的团队材料制定 30/60/90 天计划。

## 示例十：QA / CSV 负责人

**输入**：JD 要求 GxP 计算机化系统验证、偏差/CAPA 与审计；候选人有实验室系统上线经历。

**验证重点**：风险评估、验证边界、数据完整性、供应商管理、审计证据与业务冲突处理。

**工作样本**：给出一项审计发现，要求判断影响、临时控制、根因调查、CAPA 与有效性检查。

## 示例十一：生物工艺开发科学家

**输入**：JD 要求发酵工艺开发与放大；候选人有摇瓶和 5 L 经验，但无中试记录。

**评估重点**：DOE、关键工艺参数、传质/混合、可比性、偏差排查与技术转移。将“可放大能力”标为缺失，不由小试经验自动推断。

**工作样本**：给出放大后产量下降和代谢副产物上升的数据，要求构建排查树与最小验证实验。

## 示例十二：客户成功 / 解决方案工程师

**输入**：JD 要求连接技术产品与大型客户；候选人曾做后端开发和售前支持。

**评估重点**：需求澄清、技术转译、部署、采用率、升级处理与商业敏感度。

**工作样本**：模拟客户发现会议；客户要求一个高风险定制功能，候选人需澄清真实目标并提出替代方案。

## 示例十三：采购经理

**输入**：JD 要求实验室高值设备采购、供应商管理与全生命周期成本控制。

**评估重点**：技术需求转译、TCO、招采合规、谈判、履约与利益冲突。

**行为验证**：追问一次拒绝内部强势利益相关方指定供应商的经历，以及如何保留证据和推进决策。

## 示例十四：SRE / 平台工程师

**输入**：JD 要求 Kubernetes、可观测性和事故响应；候选人有云平台运维经验。

**coding 形式**：日志聚合/限流器小题 + 故障调试工作样本；高级候选人重点看并发、降级、SLO 与复盘机制，而不是提高算法题难度。
