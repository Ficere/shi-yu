# Coding 面试题选取策略

当用户要求考察 coding 能力时，从可靠来源（首选 LeetCode，可辅以 HackerRank、CodeSignal、LintCode）选取匹配岗位与候选人特点的题目。

## 选题目原则

1. **匹配岗位技术栈**：根据 JD 的语言与技术栈（如 Python / Java / C++ / Go）与业务领域（如后端、算法、生物信息、前端）选题。
2. **匹配候选人经验水平**：
   - 初级（0-3 年）：以 Easy 为主，少量 Medium，考察基础数据结构与语法。
   - 中级（3-7 年）：Medium 为主，考察常见算法与边界处理。
   - 高级 / 负责人（7+ 年）：Medium 偏难 + 部分 Hard，或结合系统设计，考察权衡与优化。
3. **匹配岗位业务场景**：优先选与业务相关的题目（如生物信息岗选序列 / 字符串 / 图遍历，后端岗选数组 / 哈希 / 树 / DP），让题目有真实感。
4. **覆盖核心知识点**：至少覆盖数组 / 哈希、字符串、树 / 图、动态规划、双指针 / 滑动窗口等常见类别，避免单一。

## 获取题目的方法

1. 用 web 搜索或直接浏览 LeetCode 获取题目：按标签（topic tag）与难度筛选，例如搜索「LeetCode 字符串 中等 题号」「LeetCode 图遍历 medium」。
2. 确认题目信息：题号、标题、难度、标签、题面要点、示例。
3. 为每道题补充：考察点、期望解法复杂度、追问方向（如「能否优化到 O(n)」「空间能否 O(1)」「边界情况」）。
4. 引用来源：在输出中标注题目来源与链接（如 LeetCode 题号与 URL），保证可追溯。

## 推荐题目类别（按岗位）

| 岗位领域 | 优先标签 | 示例方向 |
|----------|----------|----------|
| 后端 / 通用 | 数组、哈希表、字符串、树、DP | 两数之和、最长无重复子串、LRU 缓存、二叉树遍历 |
| 算法 / 数据 | 排序、二分、图、DP | 合并区间、搜索旋转数组、岛屿数量、最长递增子序列 |
| 生物信息 / 序列 | 字符串、双指针、滑动窗口、图 | 最长公共前缀、DNA 序列、字符串匹配、序列比对简化 |
| 前端 | 数组、栈、递归、树 | 有效括号、扁平化嵌套数组、深度优先遍历 |

## 输出格式

每道题输出：

```
题目：<题号> <标题>（<难度>）
标签：<标签列表>
考察点：<核心算法 / 数据结构>
期望复杂度：<时间 / 空间>
追问方向：<优化、边界、扩展>
来源：<LeetCode 链接>
选题目理由：<与岗位 / 候选人特点的匹配说明>
```

## 注意事项

- 不要只给题号，要给出题面要点与考察点，便于面试官直接使用。
- 追问方向要具体（如「数组有序时如何优化」「数据流场景怎么做」），而非泛泛「再想想」。
- 若候选人经验与岗位要求明显不匹配，调整难度并说明理由。
- 题目来源必须真实可查，避免编造题号或链接。
